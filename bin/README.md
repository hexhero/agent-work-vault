# bin

Tool scripts. Run them from the repository root; they only need the Python 3 standard library.

Script output and comments are in Chinese for now; the commands and options below are the same in either language.

## setup.py

Run once after cloning: choose the language (copies the docs under `i18n/<language>/` into place), write `vault.config.json`, enable the pre-commit hook, sync the skill entries. `--examples` installs the example project and daily logs from `examples/<language>/` (existing files are not overwritten).

```bash
bin/setup.py --lang zh-CN --timezone Asia/Shanghai   # Chinese docs, Beijing time
bin/setup.py --lang en --examples                   # English docs, with examples
```

## vault.py and vault.config.json

Conventions shared by the scripts; not run on its own:

- The three daily-log headings, the fixed sections of a project main file, the "Project:" line under a task and the "→ [Details]" link are recognized in both Chinese and English (English: `## Tasks` / `## Log` / `## Events`, `Project:`, `→ [Details]`; project sections are in `PROJECT_SECTIONS` in `vault.py`). Use one language per file.
- `vault.config.json` in the repository root has two settings: `language` (`zh-CN` or `en`, the language of the skill entries generated by `sync_skills.py`, default `zh-CN`) and `timezone` (an IANA time zone name, used for "today" in `day_summary.py` and by the board; the `VAULT_TZ` environment variable takes precedence, and without either the machine's local time zone is used).

## unfinished_tasks.py

Pulls unfinished tasks out of the daily logs `task/YYYY-MM-DD.md`, grouped by date, with status and line number.

The status is the checkbox: `[ ]` not started, `[/]` in progress, `[?]` Review (the AI is done or needs a decision; waiting for the user), `[!]` blocked, `[x]` done, `[-]` cancelled. Everything except done and cancelled counts as unfinished; other characters used by the Task Board plugin (such as `<`) are reported as "other" and also count as unfinished.

- Only scans logs named `YYYY-MM-DD.md`; ignores `task/details/` and `task/temp/`.
- An `HH:MM` at the start of an entry is taken as its start time; entries without a time are listed too.
- Unfinished subtasks nested in sub-lists are listed as well, prefixed with `└`.

```bash
bin/unfinished_tasks.py                    # list all unfinished tasks
bin/unfinished_tasks.py -d                 # include the notes under each task
bin/unfinished_tasks.py -s blocked         # only blocked ones (repeatable: -s todo -s doing)
bin/unfinished_tasks.py --since 2026-10-01 --until 2026-10-07   # limit the log date range
bin/unfinished_tasks.py --json             # JSON output for other scripts
bin/unfinished_tasks.py --ref PROJ-123     # look up entries by ticket number (ClickUp-style PROJ-123 or a ClickUp link), including done and cancelled; repeatable
bin/unfinished_tasks.py -p demo            # only unfinished tasks linked to a project file (link in the title or the "Project:" line); repeatable
bin/unfinished_tasks.py --id T-8           # look up entries by task ID, including done and cancelled; repeatable
bin/unfinished_tasks.py --next-id          # the next free task ID (highest in all logs plus one)
bin/unfinished_tasks.py --reporter AliceChen   # only unfinished tasks from a reporter (#reporter/AliceChen at the end of the task line); case-insensitive, repeatable
bin/unfinished_tasks.py --type message     # only unfinished tasks of a type (#type/message); repeatable
bin/unfinished_tasks.py -a --type message --reporter BobLi   # -a also lists done and cancelled ones (combine with other filters)
```

Sample output:

```
== 2026-10-05  (task/2026-10-05.md)
  [/] 进行中  09:00 Title A → [Details](details/a.md)  :1
  [!] Block  12:00 Title B  :3
    └ [ ] 未开始  Subtask  :6

共 3 条未完成（进行中 1，Block 1，未开始 1）
```

JSON fields per item: `date`, `line`, `mark` (checkbox character), `status` (`todo` / `doing` / `review` / `blocked` / `other`), `status_label` (Chinese label), `start` (start time, may be null), `id` (task ID `T-N`, null if none; not included in `title`), `title`, `reporter` (the part after `#reporter/` on the task line, e.g. `AliceChen`, null if none; the tag is not included in `title`), `type`, `nested` (whether it's a subtask), `detail` (note lines), `refs` (ticket numbers mentioned in the title and notes: ClickUp-style custom IDs such as `PROJ-123` or raw IDs from ClickUp links, title ones first), `projects`.

## sync_skills.py

Installs / syncs the skills under `skills/` as this repo's project skills (`.claude/skills/`); rules in [skills/sync-skill.md](../skills/sync-skill.md).

- `skills/` wins: installs new ones, removes entries whose source is gone, overwrites entries that differ; the entry's `name` and `description` are copied verbatim from the source, and its body always points back to the source.
- Skills whose folder name differs from `name`, or without frontmatter, are reported as errors and skipped, never renamed automatically.
- Only entries generated by this script (with the fixed marker in the body) are deleted; other folders placed in `.claude/skills/` by hand, and extra files inside entry folders, only produce warnings.

```bash
bin/sync_skills.py            # install / sync and list what was installed, updated, removed
bin/sync_skills.py --check    # check only; exit code 1 on differences or errors
```

Sample output:

```
已补装  weekly-report
已更新  daily-log
已删除  old-one
共 7 个 skill：一致 5，补装 1，更新 1，删除 1，错误 0
```

## projects.py

Lists the projects under `projects/`: reads `name` and `description` from each project file's frontmatter, the same way skills are read. You can see what projects exist and what each one is without reading the bodies, then decide which project file to open.

```bash
bin/projects.py                 # one line per project: name — description
bin/projects.py -v              # plus aliases, repos, hosts, file path, files in the same-name folder
bin/projects.py demo api        # filter by keywords (matches name, aliases, description; any of them)
bin/projects.py --json          # JSON output
```

## day_summary.py

Summarizes what happened on a day: that day's entries from every project log (`projects/<project>/log.md`), plus the tasks, log and non-project events from the daily log. Project matters are only recorded in project logs, so "what did I do today" needs this to combine both sides.

```bash
bin/day_summary.py                # today (time zone: see vault.py above)
bin/day_summary.py 2026-11-11     # a given date
bin/day_summary.py -p demo        # one project only
```

## board.py

Task board: renders `projects/`, `task/` and `skills/` as a live-updating relationship graph; read-only, changes no files. The page is `bin/board.html` (its UI is in Chinese for now).

- The top is the graph: projects are file cards, unfinished tasks hang next to their project, skills are labels inside the big central circle, done / cancelled tasks are small dots around their project. Edges are task → project, task → skill (the skill name appears in the task title or notes), skill → project (projects linked from SKILL.md), project → core.
- In-progress, Review and blocked tasks are cards in their status colour; their edges to projects, skills and the core and the endpoints are drawn in the status colour with moving light dots; everything else is background.
- The core circle in the middle is Claude: icon and label in the centre, below them the remaining subscription quota for the last 5 hours and the week, today's tokens and the number of running sessions. Two rings of sectors inside show the quota (inner: 5 hours, outer: week, clockwise from 12 o'clock; bigger means more left; red below 20%); around the ring is a bar chart of output tokens per hour over the last 24 hours; clicking the core opens details (quota and reset times, token breakdown, last 7 days, per model).
- Where the quota comes from: every 15 minutes `board.py` sends the shortest possible headless request with haiku (`claude -p`, no saved session, no tools or MCP) and reads the used share and reset times from the returned rate-limit info, about ten thousand haiku tokens each time; `--quota-interval 0` turns it off, after which the core shows tokens only. Token counts come from the local session records in `~/.claude/projects`, reading only numbers and model names, never conversation content, scanned incrementally every 5 seconds. No costs.
- A row of buttons above the graph (all / in progress / Review / blocked / not started / projects / skills / done, keys `0`–`7`): clicking one brings that group to the foreground, enlarging the cards around the core with their full content ("blocked on", "pending", project, reporter), highlights related projects and skills and dims the rest; click again or press Esc to restore.
- When a new task arrives or a task's status changes, those tasks come to the foreground for 20 seconds (same effect), with a list of changes at the top (old status → new status); click anywhere or press Esc to restore early. Not triggered for more than 8 changes at once (e.g. a bulk log edit).
- Click a task to see its content: reporter, notes, `task/details/` doc, project log entries mentioning the same ticket number. Click a project for its summary, unfinished tasks, related skills, project log (last 3 days by default) and done tasks. Click a skill for its description, linked projects and tasks mentioning it. Hovering a node or a row in the lists below highlights its edges and neighbours.
- Four panels below: unfinished tasks, task counts per project (unfinished / all), follow-ups, and the event stream (entries under "## Events" in daily logs, newest first, up to 300; task IDs in events are clickable; a new event makes its task node ripple).
- The follow-up panel shows items from an optional background follow-up service if you run one (`task/follow-up.json` and `~/.local/state/follow-up/`); without one it stays empty.
- "Collapse panels" at the bottom of the graph (key `F`) folds the panels away so the graph fills the window; click again to expand; the state is kept in the browser.
- Teal by default; four dots at the top right switch the palette (teal / orange / ice blue / lime), kept in the browser. With "reduce motion" on, nodes don't float and no light dots run.
- Data reuses the parsers of `projects.py` and `unfinished_tasks.py`; skills are read from each `SKILL.md`'s frontmatter; files are checked for changes every second and pushed to the page over SSE.
- Listens on localhost only by default; `/api/doc` only serves docs under `task/details/`.
- Works on phones (nodes shrink to small cards, the foreground becomes a list); all API paths in the page are relative, so it can sit under a sub-path behind a reverse proxy. If a proxy buffers the event stream, the page falls back to polling every 5 seconds.

```bash
bin/board.py                    # http://127.0.0.1:8765
bin/board.py --port 9000
bin/board.py --host 0.0.0.0     # let other machines on the network open it
```

## lint_vault.py

Checks every doc in the repo against the conventions in [CLAUDE.md](../CLAUDE.md), [project-docs](../skills/project-docs/SKILL.md) and [daily-log](../skills/daily-log/SKILL.md); it is the machine version of those written rules, so change both together. Ignores `task/temp/`, `.obsidian/`, `.claude/`, `examples/`, `i18n/`, `oss/`.

| Check | What |
|---|---|
| frontmatter | `type` and required fields per folder (project: `name` / `description` / `aliases` / `repo` / `hosts`, `name` equals the file name; detail doc: `project` / `log`; project material: `project`) |
| links | Relative links and `[[wikilinks]]` in frontmatter resolve |
| no-task-link | Files under `projects/` don't link to `task/` (except the project log `log.md`) |
| size | Warns when a project main file exceeds 16KB, a Design (`design*.md`) or `pitfalls.md` exceeds 32KB, or a project log `log.md` exceeds 64KB |
| sections | An organized project main file (one with `## Location` or `## 位置`) may only have the fixed level-2 sections (Location, Resources, Read on demand, Where to look, How to, Red lines, Pitfalls, Related, or the Chinese equivalents) in that order; one with a same-name folder needs "Read on demand"; unorganized ones get a single summary warning |
| project-log | Level-2 headings in project logs `log.md` and `log-YYYYqN.md` can only be `## YYYY-MM-DD`, in reverse date order |
| index | The README indexes under docs list every file (`projects/` has no index file; use `bin/projects.py`) |
| filename | File names under `projects/` and `task/details/` |
| daily-log | Daily logs: heading order (Tasks, Log, Events), tasks under "## Tasks", no checkboxes in the log and events parts, one line per event "- HH:MM what was done"; warns when a task has more than 10 sub-lines |
| task-id | Unfinished top-level tasks need a task ID `T-N`; IDs are unique across all logs; the reporter tag only on top-level task lines, formatted `#reporter/AliceChen` |
| skills | Runs `sync_skills.py --check` |

```bash
bin/lint_vault.py       # exit code 1 on errors; warnings don't affect it
bin/lint_vault.py -q    # errors only
```

The repo ships a pre-commit hook (`.githooks/pre-commit`) that rejects commits with errors. Enable it once after cloning: `git config core.hooksPath .githooks` (`bin/setup.py` does this for you).
